# 功能清单与后续优化方向

本文档回答两个问题：**这个软件现在能做什么**、**接下来还值得做什么**。
用法与安装见 [README](../README.md)，实现细节见 [CORE_IMPLEMENTATION](CORE_IMPLEMENTATION.md)。

---

## 1. 怎么打包、怎么运行

### 1.1 三种运行方式

| 方式 | 命令 | 适合谁 |
|---|---|---|
| **双击运行（推荐给评审）** | 桌面快捷方式，或 `release/Lumen-conv-便携版/Lumen-conv.exe` | 不想装环境、只想看效果 |
| 开发模式 | `npm run setup` → `npm run dev` | 要改代码 |
| 生产构建后运行 | `npm run build` → `npx electron .` | 验证打包前的产物 |

**便携版是完全自包含的**：里面已带 Electron 运行时 + ffmpeg + ffprobe（合计约 602 MB），
目标机器**不需要装 Node、不需要装 ffmpeg**，复制整个 `Lumen-conv-便携版/` 目录到任何 Windows x64 机器都能直接跑。

### 1.2 打包命令

```bash
# 便携版（离线可用，会先构建再打包）
npm run dist:portable

# 便携版 + 同时在桌面创建快捷方式
node scripts/package-portable.mjs --build --shortcut

# 只重新打包（复用已有的 dist / dist-electron，更快）
node scripts/package-portable.mjs
```

产物结构：

```
release/Lumen-conv-便携版/
├── Lumen-conv.exe              # 主程序（200.4 MB）
├── *.dll / *.pak / locales/    # Electron 运行时
└── resources/
    ├── app.asar                # 应用代码（主进程 + preload + 渲染层）
    └── bin/
        ├── ffmpeg.exe          # 139.1 MB
        └── ffprobe.exe         # 138.9 MB
```

### 1.3 为什么没做 NSIS 安装包

`npm run dist:nsis` 需要 electron-builder 的完整工具链（app-builder-bin / nsis / winCodeSign），
在受限网络下会 `Timeout awaiting 'request' for 600000ms`；它下载 Electron 用的缓存目录
与 `@electron/get` **不通用**，所以本地已有 zip 也不会被复用。两次实测都卡在同一处，
于是改为 `scripts/package-portable.mjs` 离线手工组装。详见 [DECISIONS](DECISIONS.md) 的打包决策条目。

### 1.4 已知的两个打包瑕疵（不影响功能）

1. **exe 内嵌图标是 Electron 默认图标**。electron-winstaller 附带的 rcedit 0.2.0（2019 年）
   在本环境对**任何** exe 都报 `Fatal error: Unable to load file`——已对照测试过
   electron.exe、rcedit 自身副本、系统 `notepad.exe`，全部失败，所以与项目路径含中文无关，
   也不是文件大小问题。**补偿措施**：桌面快捷方式的 `IconLocation` 指向 `build/icon.ico`，
   用户从桌面看到的仍是正确图标。
2. **没有桌面/开始菜单的"安装"过程**：便携版不写注册表、不加开始菜单项，删掉目录即卸载。

## 2. 现在有什么功能

### 2.1 文件输入与挑选

- **拖拽任意位置即添加**（不用瞄准某个虚线框），也支持「添加文件」按钮和 `Ctrl+O`
- **文件对话框支持多选**（`multiSelections`），可以一次选中一批文件
- 一次可拖入多个文件；分析并发上限 3 路，避免一次拖 50 个文件把 ffprobe 打爆
- **每个文件带勾选框**，配合「全选 / 取消全选」可以挑着转：
  - 未勾选任何文件 → 「开始转换」转**全部**可转换文件（快捷路径）
  - 勾选了若干 → 只转**勾选的那些**，按钮上会实时显示数量
- 拖入非视频文件不会崩：卡片显示红色「无法读取」+ 具体原因，可单独移除
- 已添加过的文件自动去重

### 2.2 视频信息展示

- **容器**：MP4 / QuickTime、Matroska、WebM…（并对 WebM 做特殊处理，避免显示成 MKV）
- **时长 / 文件大小 / 总码率**
- **画面**：显示分辨率（已按非方形像素与旋转角校正）、帧率
- **视频编码**：H.264 / H.265 / VP9… + profile
- **色彩**：像素格式，10bit 与 **HDR** 会额外打标签
- **旋转**：手机竖拍会提示"转换时会自动转正"
- **音频**：编码、声道（单声道 / 立体声 / 5.1 环绕）、采样率
- **音轨数 / 字幕数 / 章节数**
- 可一键「在文件夹中显示」

### 2.3 缩略图

- 自动生成缩略图并显示时长角标
- **智能选帧**：先用 `blackdetect` 找片头黑场，再按 `signalstats` 平均亮度挑帧，避免得到一张全黑封面
- 按「路径 + 大小 + 修改时间」做磁盘缓存，第二次进入秒出
- 抽帧失败降级为占位图，不阻断转换

### 2.4 转换：先说「要拿去干什么」

主入口是 **8 张用途卡片**，而不是让你先研究编码器。选一个用途，容器 / 编码器 /
分辨率 / 质量 / 体积上限就都定好了：

| 用途 | 会发生什么 |
|---|---|
| 发微信 / QQ | H.264 + AAC，压到 **≤100MB**，1080p 上限（微信在部分机型上放不了 H.265，所以这里固定用兼容性最好的 H.264） |
| 手机存着看 | 压到 1080p + 小体积档，适合清手机空间 |
| 拿去剪视频 | 高画质 + H.264 的 MP4（剪辑软件普遍不吃 H.265 与 MKV） |
| 老电视 / 车载 U 盘 | 最保守的规格：H.264 + AAC + 1080p，避开 HDR 与高帧率 |
| 长期存档 | H.265 + 高画质，同观感下体积最小 |
| 只要声音 | 抽出音轨转 MP3 |
| 做 GIF 动图 | 调色板两遍法，并提示先裁剪到几秒 |
| 只换容器（极速） | `-c copy`，几秒完成、画质零损失 |

**目标体积上限**：直接填「≤100 MB」这样的硬约束，用**两遍编码**精确命中，
不需要"猜一档质量 → 转完看结果 → 不行再转一遍"。
体积优先时质量档位自动禁用并说明原因（码率是由体积反推出来的，不是猜的）。

**兼容性预检**：转换**之前**就检查"这样转出来能不能播"。例如把编码器改成 H.265
又选了「老安卓电视」，界面立刻提示：

> ⚠️ 老安卓电视 / 车机 通常播不了 H.265
> 建议改用 H.264。这类设备解码能力弱，通常不接受 H.265、AV1、VP9，也不支持 HDR
> 　　　　　　　　　　　　　　　　　　　　　　　　　　［一键修复］

同类提示还覆盖：音频编码不被设备支持、HDR/10bit 会被转成普通色彩、
目标体积小到连音频都装不下（直接标为必须处理）、源编码装不进目标容器等。

**格式仍可手动指定**（高级选项里），改了会覆盖用途的推荐设置，也可以再点一次用途卡片恢复。

底层能力（9 个预设 / 7 种容器）没有变，只是入口从"选格式"改成了"选用途"：

| 预设 | 输出 |
|---|---|
| MP4 通用兼容 | H.264 + AAC，兼容性最好 |
| MP4 1080p 压缩 | 压到 1080p，体积明显变小 |
| H.265 小体积 | HEVC，同画质约为 H.264 的 60% |
| WebM 网页视频 | VP9 + Opus |
| MKV 收藏 | 保留多音轨与字幕 |
| 极速换壳 | `-c copy`，几秒完成、画质零损失 |
| 导出 MP3 / M4A | 只留音频 |
| GIF 动图 | 调色板两遍法 |

**质量与尺寸**：5 档质量（存档级 / 高画质 / 均衡 / 小体积 / 极小体积）、7 档分辨率、5 档帧率，
并且每调一个参数都实时显示「预计产物体积」。

**高级选项**：视频编码器（含显卡加速，不可用的会置灰并说明原因）、音频编码、字幕轨道勾选、
裁剪片段（起止时间）、保留元数据与章节、文件名模板（`{name}` `{preset}` `{date}`，带实时预览）。

### 2.5 任务队列

- 并发数可配（1-4，默认 2）
- 实时进度：**百分比 + 速度倍率 + 剩余时间 + 已用时**；总时长未知时走不确定进度条而不是假装从 0% 爬
- 取消：杀整棵进程树，并**删掉半成品文件**（不会留下 0 字节的 .mp4）
- 失败：中文原因 + 修复建议，并可展开**ffmpeg 原始日志**、一键复制诊断信息、重试
- 完成：产物大小与压缩比（如 `661 KB → 706 KB（原片 107%）`）、「打开位置」按钮
- **每个任务可展开查看完整 ffmpeg 命令原文**——这是"确实在用命令行"的直接证据

### 2.6 设置与诊断

- ffmpeg / ffprobe 实际路径与版本，支持手动指定（文件对话框选择或粘贴路径）
- **每个编码器的可用性**：硬件编码器是真跑一次 0.2 秒编码验证的结果，不是只查列表
- 并发数、默认输出目录、主题（跟随系统 / 深色 / 浅色）、完成通知、完成后打开目录
- 缩略图缓存清理、恢复默认设置

### 2.7 自动化优化（用户不用管，但能感觉到）

- 硬件编码器自动探测（本机 Intel QSV 可用，NVENC/AMF 如实标为不可用）
- HDR → SDR 色调映射（不做的话转出来画面发灰）
- 旋转自动转正、目标分辨率高于源时只缩不放
- 磁盘空间预检、容器兼容性前置校验（不合格的在入队前就拦下）
- 输出自动改名避免覆盖（`名称 (1).mp4`）
- MP4 加 `+faststart`（索引前置，网页可边下边播）

## 3. 后续可以优化的方向

按「投入产出比」排序，不是按难度。

### 3.1 高价值、工作量可控

| # | 方向 | 解决什么问题 | 大致做法 |
|---|---|---|---|
| 1 | **让用户手动挑封面** | 智能选帧仍可能挑到不理想的画面（比如人物闭眼、台标遮挡） | `extractFrameAt()` 已经写好但没被 UI 调用；加一个"换一张"按钮 + 时间轴拖拽即可 |
| 2 | **两遍编码（two-pass）** | 目标体积精确可控——现在只能"选个质量档次看运气" | 用户要的是"压到 100 MB 以内"这类硬约束，two-pass 是标准解 |
| 3 | **转换前后对比预览** | 用户无法在转换前判断"这个质量档够不够" | 抽同一时间点的前后两帧做并排对比滑杆 |
| 4 | **字幕抽取 / 烧录** | 目前字幕只能"保留"，不能导出 srt、不能硬字幕 | 抽取用 `-map 0:s:N out.srt`；烧录用 `subtitles=` 滤镜（两者都是命令行能力，实现成本不高） |
| 5 | **媒体信息图表化** | 现在是纯文字，码率波动、音量分布都看不出来 | 用 `ffprobe -show_frames` 画码率曲线；用 `astats`/`ebur128` 画音量波形 |
| 6 | **失败自动降级重试** | 硬件编码失败时用户得自己改回软编码再点一次 | 捕获到编码器初始化失败就自动换软编码重试一次，并告知用户 |

### 3.2 中等价值

| # | 方向 | 说明 |
|---|---|---|
| 7 | 预设导入 / 导出 | 团队里共享一套参数（JSON），或导出成一条可复制的命令行 |
| 8 | 命令行接口（CLI） | 让本项目能被脚本调用，做批处理与自动化流水线 |
| 9 | 监视文件夹自动转换 | 录屏/下载目录一有新文件就自动转，适合固定工作流 |
| 10 | 输出命名批量规则 | 现在模板是全局的；批量场景下常需要 `{index}` 递增、按源目录归档 |
| 11 | 转换历史持久化与搜索 | 现在重启即丢，找不到"上周转过的那个文件" |
| 12 | 断点续传 / 分段并行 | 长视频转换中断只能整段重来 |
| 13 | 图片序列 / 音频格式扩展 | 现在偏视频；加 WebP/AVIF 导出、WAV/FLAC 无损音频等 |

### 3.3 工程与质量

| # | 方向 | 说明 |
|---|---|---|
| 14 | **接单元测试框架** | 目前只有端到端冒烟测试；`format.ts` 的格式化、`progress.ts` 的解析、`errors.ts` 的规则匹配都适合补表驱动的边界用例 |
| 15 | **在真显卡上验证硬件编码参数** | 本机只有 Intel QSV 可用，NVENC / AMF 的 `-cq` / `-b:v` 参数组合**没有在真卡上跑过**，这是目前最实在的未验证项 |
| 16 | 清理未引用的预留代码 | `pickBestVideoCodec()`、`clearCapabilityCache()`、`warmThumbnail()`、`extractFrameAt()` 目前只有定义没有调用 |
| 17 | 缩小分发包体积 | 现在 602 MB。可换 LGPL/精简版 ffmpeg（代价：H.264/H.265 软编码不可用），或做成首次启动按需下载编码器 |
| 18 | 代码签名 | 现在会触发 SmartScreen「未知发布者」；正式分发需要证书 |
| 19 | 多语言（i18n） | 界面文案目前硬编码中文 |
| 20 | 无障碍与键盘可达性 | 补齐 Tab 顺序、快捷键提示（现在只有 `Ctrl+O` 有提示，`Ctrl+1/2/3` 没提示） |

### 3.4 需要先说清楚取舍的

- **AI 增强类**（自动识别场景切分、智能推荐码率、内容感知裁剪）：很有吸引力，但会引入模型依赖与不可解释的失败，
  且与"纯 ffmpeg 命令行"的项目定位有张力。如果要做，建议作为**独立可选模块**，不进入主转换链路。
- **云转码**：能解决本机性能问题，但会把"客户端工具"变成"客户端 + 服务"，与要求 6 的定位有冲突。

## 4. 一句话总结

现在这个版本已经覆盖了「看清视频信息 → 选一个合适的输出 → 看着它转完 → 拿到文件」的完整闭环，
并且把容易出错的环节（片头黑场封面、显卡加速不可用、容器不兼容、磁盘满、取消后残留半成品）
都做了处理。下一步最有价值的三件事是：**让用户能自己挑封面**、**支持按目标体积压（two-pass）**、
**补上单元测试**。
