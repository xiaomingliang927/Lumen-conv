# 边界与异常用例记录

对应笔试要求第 7 条："不要做的东西自己都用不明白甚至都不测试"。

本文档记录**实际验证过的**边界场景与结果。分两部分：

- A 部分：由 `npm run smoke`（主进程与 ffmpeg 链路，**56 项**）与界面自检三级命令
  （`smoke:ui` **14 项** / `smoke:ui:file` **54 项** / `smoke:ui:full` **66 项**）自动化覆盖，可重复执行、都有退出码
- B 部分：需要人工在界面上确认的场景（自动化成本高于收益，或依赖真实窗口交互）

> 环境：Windows，Node v26.6.0，Electron 38.8.6，ffmpeg / ffprobe 见 `npm run setup` 输出。

### A2. 参数与容器组合

| 场景 | 期望行为 | 结果 |
|---|---|---|
| 未知预设 id | 抛 `CommandBuildError`，消息为"未知的预设：xxx" | ✔ |
| 直通 + 源编码装不进目标容器（THEORA → MP4） | 入队前拦截，提示"源视频是 THEORA 编码，装不进 MP4 容器" + 修复建议 | ✔ |
| 直通 + VP9 → MP4（**合法组合**） | 必须放行，不能过度拦截 | ✔ |
| 直通 + H.264 → WebM（非法组合） | 拦截并给出人话提示 | ✔ |
| NVENC 编码器（软/硬件参数差异） | 使用 `-cq` 而非 `-crf`，不混用 | ✔ |
| 目标分辨率高于源分辨率 | 不生成 `scale` 滤镜（只缩不放） | ✔ |
| 目标分辨率低于源分辨率 | 生成 `scale=-2:<h>:flags=lanczos` | ✔ |
| **GIF 预设（含前置滤镜）** | 单次调用的**内联**调色板两遍链：`fps=15,split[a][b];[a]palettegen=…[p];[b][p]paletteuse=…`，前置滤镜被保留在同一侧，链首不是逗号 | ✔ |
| **GIF 预设（前置滤镜为空）** | 回归用例：源 640×480 + 目标 480p + 不改帧率 ⇒ 没有前置滤镜，滤镜链必须**以 `split` 开头**、无前导逗号、无连续逗号 | ✔ |
| 纯音频预设 | 命令含 `-vn`，使用 `libmp3lame` | ✔ |
| 裁剪区间 | `-ss 1.000 -t 2.000`，产物回读时长 2.00s | ✔ |

> GIF 这两条用例针对的是同一个真实缺陷：早期实现把调色板链拼在 `${已有滤镜},` 之后，
> 前置滤镜为空时会生成以逗号开头的滤镜链，ffmpeg 报 `No such filter: ''` 并产出 0 字节文件。
> 第一条用例因为显式传了 `fpsId: '15'` 会注入 `fps` 滤镜、**恰好绕开**该分支，
> 所以必须补第二条"前置滤镜为空"的回归用例；两条都在，另外还有一条真实转码的回归（见 A3）。

### A7. 假通过与断言强化（真实案例）

界面自检的检查项是**递进追加**的：`smoke:ui` 14 项 → `smoke:ui:file` 54 项 → `smoke:ui:full` **66 项**。

- **14 项基础**（`smoke:ui`）：10 项首屏元素（窗口标题 / 标题栏 / 侧边导航 / 文件区 / 详情面板 / 空状态 / 全局样式 / 主题 / preload API / ffmpeg 状态）
  + 4 项逐页检查（任务队列页有内容 / 设置页有内容 / 导航切换生效 / 截图已生成）
- **+40 项"加载真实文件后"**（`smoke:ui:file`，共 54 项）：
  - 加载真实文件后 **8 项**：视频信息摘要（收起态）、缩略图、时长角标、用途卡片全部渲染（8 张）、兼容性预检已运行、体积预估、分辨率/编码写进摘要、截图已生成
  - 视频信息折叠 **1 项**：可展开看完整明细（8 行），收起后回到一行摘要
  - 用途交互 **3 项**：点击后选中态切换 / 勾选标记唯一 / 体积预估联动
  - 模式切换 **4 项**：两个模式按钮存在 / 推荐模式隐藏全部专业参数 / 自定义模式出现专业参数入口 / 切回推荐后重新隐藏
  - **模式差异的可见性 4 项**（本轮新增，见下）：首屏内容确实不同 / 首屏可见区块有差别 / **自定义模式专业参数入口出现在首屏** / 推荐模式首屏能看到"用途"与"在哪播"
  - 自检前置 **1 项**：能进入自定义模式并展开专业参数
  - 兼容性预检 **3 项**：做出"播不了"的组合时出现警告 / 警告里有可操作建议 / 一键修复能消除警告
  - 参数偏离提示 **3 项**：手动改格式后用途仍保留 / 出现"已偏离推荐值"提示 / 「恢复推荐值」能把参数收回来
  - 输出命名 **4 项**：提供常用命名选项含自定义 / 切换选项改变预览 / 选自定义出现模板输入框 / 自定义模板反映到预览
  - 专业参数 **1 项**：展开后不横向溢出（实测最宽元素 `field@336`，面板宽 400px）
  - 用途跨文件保留 **1 项**
  - 文件勾选 **3 项**：每个文件都有勾选框 / 勾选后按钮计数联动 / 提供全选入口
  - 质量下拉 **4 项**：档位完整 / 切换后值生效 / 体积预估联动 / 跨文件保留
- **+12 项"应用内真跑转换"**（`smoke:ui:full`，共 66 项）：含 1 项「队列页截图已生成」（只在转换成功时追加）、
  1 项**勾选语义的硬断言**（只勾选 1 个文件时，队列里必须只有那 1 个任务）、
  以及 1 项**把界面选择与 ffmpeg 命令对上的硬断言** —— 它按当前模式分两支断言：
  有体积上限时要求 `-b:v` + `-pass 2` 且**不得出现 `-crf`**；
  无体积上限时要求「极小体积」对应 `-crf 34`

这三组交互断言都是被用户反馈逼出来的，前两组还指向**同一个根因**：

> 有用户先问"点预设卡片右侧的标签没反应"，后又问"质量下拉是可以用的吗"。
> 查下来是同一个 bug 的两种表现：**预设 / 质量 / 分辨率 / 帧率 / 编码器 / 音频 / 文件名模板
> 全都写进了「按文件的 overrides」**，而界面回显读的是别的来源，于是
> ① 点预设卡片高亮不动（看起来点了没反应）② 调好的参数一换文件就全丢。
>
> 修复方式是按语义把参数分成两类：
> **全局偏好**（上述这些，表达"我想转成什么样"）写全局 `options`；
> **文件特有设置**（裁剪区间、字幕轨道勾选）保留按文件覆盖。
>
> 第三组（文件勾选）来自另一个问题："可以一次性选择多个文件吗"——
> 一次选多个文件本来就支持，但原先**没法挑选**：要么全转、要么先把不想转的逐个删掉。
> 于是加了每个文件的勾选框与「全选 / 取消全选」，语义是
> **未勾选任何文件 = 转全部可转换文件**（保留原来的快捷路径），
> **一旦勾选就只转勾选的**。批量路径另在 `npm run smoke` 里用真实 `ConversionEngine`
> 验证并发调度（3 个任务、并发 2、输出路径互不重复、进度都到 100%）。
> 控件回显统一改用 `effectiveOptions(file)`（全局 + 本文件覆盖），
> 保证"界面显示的值"就是"真正会被用于转换的值"。

"应用内真跑转换"这一组则是被另一条真实缺陷逼出来的：

| 案例 | 内容 |
| --- | --- |
| **缺陷** | Vue 响应式代理导致 IPC 结构化克隆失败，**「开始转换」按钮静默失效**：`effectiveOptions()` 合并出的数组字段（`subtitleStreamIndexes` / `audioStreamIndexes`）是 Proxy 数组，`ipcRenderer.invoke` 的结构化克隆无法克隆 Proxy，抛 `An object could not be cloned.`，队列里什么都没有、界面也不报错。**影响面比最初观察到的大**：`options` 这个 `ref` 里的同名字段本身就是 Proxy 数组，所以旧表达式下**每一次**点「开始转换」都会失败，而不是只有"改过字幕"之后才失败（最小复现实验见 `SESSION_SUMMARY.md` 第 5.1.1 节） |
| **为什么原断言会假通过** | 最早的断言只要求"截图生成成功 / 队列里有任务卡片"。而点击之前，自检里那条"直接调 `createJobs` 诊断"产生的任务**还在队列里**，于是"队列里有任务"在**按钮完全失效**的情况下同样成立——断言被另一条路径满足了 |
| **怎么改才暴露** | ① 点击前先 `engine.remove()` 清空队列；② 记录 `beforeClick`，点击后要求 `engine.list().length > beforeClick`（实际是 **0 → 1**）；③ 断言名改成"按钮点击**真的创建了**任务"，把"点击"和"入队"用副作用绑在一起 |
| **同时修掉的第二层陷阱** | `executeJavaScript` 的表达式写成 `void el.click(); true` 是不行的：`void` 只丢弃值，DOM 节点仍会作为表达式中间值被结构化克隆，同样抛 `An object could not be cloned.` 并让整个 `await` 失败。现在所有表达式一律包成 IIFE，并以基本类型收尾 |
| **可复现的验证方式** | `npm run smoke:ui:full` → **66/66 通过、退出码 0**，控制台无任何 `An object could not be cloned.`，且 `docs/screenshots/queue-done.png` 里能看到真实产物（3.15 MB、状态「已完成」、进度 100%） |

**这条案例给出的通用规则**（已写进代码注释，避免以后被"简化"回去）：

1. **断言要落在"这次操作造成的副作用"上**，而不是"流程看起来跑完了"。带前置清理 + 数量/状态变化的断言才不可被旁路满足。
2. **一个失败路径不报错，就等于没有测试**。凡是跨进程的调用，异常都要转成用户可见的提示（toast）或明确的检查项失败。
3. **别让"另一条成功路径"为被测路径背书**。诊断用的直接 IPC 调用很有价值（能区分"IPC 坏了"还是"按钮路径坏了"），
   但它必须**先清场**，否则它自己就成了假通过的来源。

> 这条缺陷的完整复盘（根因三段链条、为什么前两轮自测没抓到、四条预防措施）见
> `docs/SESSION_SUMMARY.md` 第 5.1.1 节；对应决策见 `docs/DECISIONS.md` 的 D-016。

**第四类假通过：断言自己证明自己**（本轮修「推荐 / 自定义看不出区别」时发现）

判定"两种模式首屏有差别"的原断言是：

```js
rec.blocks.filter(可见) !== cus.blocks.filter(可见)       // 只比较，不打印
`推荐首屏：${rec.blocks.filter(可见)}`                     // 证据只打印推荐那一侧
```

它会通过、也确实比较了两个字符串——但日志里**只有推荐模式的首屏**，
读者无法判断自定义模式首屏究竟长什么样，也无法判断"差别"是不是只差一个空字符串。
**证据不完整时，断言等于不可复核。** 现在改成两侧都打印：

```
推荐首屏：视频信息@152 | 你要拿去干什么@235 | 在哪播 / 多大体积@646
自定义首屏：专业参数@152 | 视频信息@205 | 你要拿去干什么@288 | 在哪播 / 多大体积@699
```

并按这次改动的**目的**补了一条独立断言：`自定义模式：专业参数入口出现在首屏（不用滚动就能看到）`。
通用规则：**日志要能让没读代码的人直接判断对错**；"比较两个值"的断言，两个值都要打出来。

### A8. 打包态（便携版）自检：**66/66 通过、退出码 0**

**为什么要单独记一条**：开发态 66/66 全绿**不能**推出打包态也能跑。
打包后运行环境变了——`app.getAppPath()` 不再指向项目根，而是指向 `...\resources\app.asar`（一个**文件**），
`process.resourcesPath` 才有意义，输出目录变成 exe 所在目录。
这些差异**只有真的把打包产物跑起来才会暴露**（本轮就因此抓到一个 `ENOTDIR`，见下）。

| 项目 | 内容 |
| --- | --- |
| 被测对象 | `release/Lumen-conv-便携版/Lumen-conv.exe`（**200.4 MB**，由 `npm run dist:portable` 离线组装） |
| 命令 | `release/Lumen-conv-便携版/Lumen-conv.exe --smoke \
  --smoke-file=<绝对路径> --smoke-assets=<仓库的 test-assets 目录> --smoke-convert` |

### A9. 真实素材验证：`npm run test:real:convert`

**为什么要单独做这一层**：`npm run smoke` 用的是 `testsrc2` 彩条 + 正弦音，
画面干净、无旋转、无字幕、无多音轨、文件名全 ASCII。
"干净素材测不出来"不是推测 —— 下面这个真 bug 就是靠换素材才暴露的。

**素材**（`npm run samples` 生成，全部由 ffmpeg 自带能力合成，无需外部下载）：

| 素材 | 模拟的真实场景 |
|---|---|
| `rot90.mp4` | 手机竖拍：720×1280 + **显示矩阵旋转 90°**（用 `-display_rotation 90` 生成，输入侧选项） |
| `vfr-screen.mp4` | 录屏：可变帧率（丢帧 + 重置时间戳） |
| `我的 测试 视频.mp4` | 文件名含**中文与空格** |
| `subs-multi.mkv` | 两条软字幕（chi / eng） |
| `multi-audio.mkv` | 两条音轨：**5.1 AC3** + 立体声 AAC |
| `very-short.mp4` | 0.8 秒，测时长边界 |
| `uhd-4k.mp4` | 3840×2160，测缩放 |
| `broken.mp4` / `empty.mp4` | 损坏与空文件 |

**结果：23 项全部通过**（13 项探测行为 + 9 项真实转换回读 + 1 项格式检查），
每条转换用例都会 `ffprobe` 回读产物并断言关键属性
（旋转是否转正、字幕是否保留、音轨数、缩放后尺寸、纯音频判定）。

#### 这一层抓到的真 bug：旋转被转了两次

| 项 | 内容 |
|---|---|
| **现象** | `rot90.mp4`（720×1280 + rotation=90）转换后产物仍是 **720×1280**，即"自动转正"没生效 |
| **根因** | 旧实现在源带旋转元数据时追加 `transpose=1`，注释理由是"重新编码后元数据可能丢失"。但现代 ffmpeg **默认就会自动应用显示矩阵并清除旋转标记**，我们再转一次等于**转了两次，正好抵消** |
| **对照实验**（同一源文件） | ① 不加 `transpose` → 产物 **1280×720 ✅**；② 加 `transpose=1`（旧实现）→ 产物 **720×1280 ❌**；③ `transpose=1` + 输入侧 `-display_rotation 0` → 1280×720 ✅ |
| **影响** | 比不处理更糟：产物既退回竖版、又**丢掉了旋转标记**，播放器里显示就是横躺的 |
| **修复** | 不再手动 `transpose`；只按显示高度（旋转 90/270 时宽高互换）参与"只缩不放"的基准计算。命令里现在**不应出现 `transpose`**，并有一条断言专门防止它被"顺手加回来" |
| **顺带发现** | 原来 `npm run smoke` 里那条"旋转元数据处理"用例是**假通过**：断言写在 `if (v.rotation === 90)` 里，而合成素材的 `rotate=90` 在新版 ffmpeg 下不再被保留（探测回来是 0），所以那句断言从未执行，用例每次走 else 分支"跳过"并算通过 |
| **怎么修测试的** | 分两层：① 用合成的探测结果验证命令装配规则（不依赖素材）；② 用真实的 `rot90.mp4` 跑一次真实转码并回读产物尺寸 |

**这条案例的通用教训**：`testsrc2` 这类"干净素材"只能证明链路跑得通，
**证明不了功能是对的**。而把断言写在可能不执行的分支里，跳过会被静默当成通过 ——
两者叠加，就会得到一个"全绿但功能是坏的"测试套件。
