# 边界与异常用例记录

对应笔试要求第 7 条："不要做的东西自己都用不明白甚至都不测试"。

本文档记录**实际验证过的**边界场景与结果。分两部分：

- A 部分：由 `npm run smoke` 自动化覆盖，可重复执行
- B 部分：需要人工在界面上确认的场景（自动化成本高于收益，或依赖真实窗口交互）

> 环境：Windows，Node v26.6.0，Electron 38.8.6，ffmpeg / ffprobe 见 `npm run setup` 输出。

---

## A. 自动化覆盖（`npm run smoke`）

最近一次执行：**48 项全部通过**（0 失败，详见命令行输出）。

运行环境：Windows x64，Node v26.6.0，Electron 38.8.6，
`resources/bin/` 下 ffmpeg 与 ffprobe 均为 `ffmpeg version N-126435-gf93cd72dde-20260906`（各约 139 MB）。

### A1. 文件与格式异常

| 场景 | 构造方式 | 期望行为 | 结果 |
|---|---|---|---|
| 完全不是视频的文件 | 写入文本内容并改名为 `.mp4` | 报"文件里没有找到任何音视频轨道"，不抛堆栈 | ✔ |
| 0 字节文件 | 写入空文件 | 在调用 ffprobe **之前**拦截，提示"文件大小为 0 字节，可能下载未完成或已损坏" | ✔ |
| 损坏文件抽帧 | 同上非视频文件 | 返回 `{filePath:null, error}`，不抛异常、不崩溃 | ✔ |
| 纯音频文件（MP3） | 用 lavfi 合成正弦音 | 探测到 `hasVideo=false`，转换走音频路径 | ✔ |
| 目录而非文件 | 代码路径显式判断 `isDirectory()` | 提示"这是一个文件夹，不是视频文件" | ✔ |

### A2. 参数与容器组合

| 场景 | 期望行为 | 结果 |
|---|---|---|
| 未知预设 id | 抛 `CommandBuildError`，消息为"未知的预设：xxx" | ✔ |
| 直通 + 源编码装不进目标容器（THEORA → MP4） | 入队前拦截，提示"源视频是 THEORA 编码，装不进 MP4 容器" + 修复建议 | ✔ |
| 直通 + VP9 → MP4（**合法组合**） | 必须放行，不能过度拦截 | ✔ |
| 直通 + H.264 → WebM（非法组合） | 拦截并给出人话提示 | ✔ |
| NVENC 编码器（软/硬件参数差异） | 使用 `-cq` 而非 `-crf`，不混用 | ✔ |
| 目标分辨率高于源分辨率 | 不生成 `scale` 滤镜（只缩不放） | ✔ |
| 目标分辨率低于源分辨率 | 生成 `scale=-2:<h>:flags=lanczos` | ✔ |
| **GIF 预设（含前置滤镜）** | 单次调用的**内联**调色板两遍链：`fps=15,split[a][b];[a]palettegen=…[p];[b][p]paletteuse=…`，前置滤镜被保留在同一侧，链首不是逗号 | ✔ |
| **GIF 预设（前置滤镜为空）** | 回归用例：源 640×480 + 目标 480p + 不改帧率 ⇒ 没有前置滤镜，滤镜链必须**以 `split` 开头**、无前导逗号、无连续逗号 | ✔ |
| 纯音频预设 | 命令含 `-vn`，使用 `libmp3lame` | ✔ |
| 裁剪区间 | `-ss 1.000 -t 2.000`，产物回读时长 2.00s | ✔ |

> GIF 这两条用例针对的是同一个真实缺陷：早期实现把调色板链拼在 `${已有滤镜},` 之后，
> 前置滤镜为空时会生成以逗号开头的滤镜链，ffmpeg 报 `No such filter: ''` 并产出 0 字节文件。
> 第一条用例因为显式传了 `fpsId: '15'` 会注入 `fps` 滤镜、**恰好绕开**该分支，
> 所以必须补第二条"前置滤镜为空"的回归用例；两条都在，另外还有一条真实转码的回归（见 A3）。

### A3. 真实转码（非模拟，实际调用 ffmpeg 并回读产物）

| 转换 | 实测结果 |
|---|---|
| MP4 → MP4（H.264 重编码） | 706 KB，产物编码回读为 h264 ✔ |
| MP4 → MP4（`-c copy` 直通） | 661 KB，明显快于重编码 ✔ |
| MP4 → WebM（VP9 + Opus） | 641 KB，容器回读为 **WebM**（曾因 `format_name` 解析 bug 显示成 Matroska，已修复）✔ |
| MP4 → H.265（HEVC） | 247 KB，产物编码回读为 hevc ✔ |
| MP4 → MP3（提取音频） | 142 KB，产物 `hasVideo=false` ✔ |
| MP4 → GIF（调色板两遍法，带 `fps` 前置滤镜） | 694 KB ✔ |
| **回归：低分辨率源直接用 GIF 默认预设（无前置滤镜）** | 640×480 源 + 480p 档 + 不改帧率，产物 **1609 KB**，滤镜链以 `split` 开头 ✔ |
| 裁剪 1s-3s → MP4 | 产物回读时长 2.00s ✔ |
| 小体积档 + 360p 压缩 | 661 KB → 250 KB（**38%**）✔ |

### A4. 错误翻译

| ffmpeg 原始输出 | 期望分类 | 期望提示 | 结果 |
|---|---|---|---|
| `No space left on device` | `disk-full` | "磁盘空间不足" + 清理建议 | ✔ |
| `Cannot load nvcuda.dll` | `unsupported-codec` | "当前环境不支持所选的编码器"，引导去**「高级选项 → 视频编码器」改回软编码** | ✔ |
| `Could not find tag for codec vp9 … not supported in container` | `unsupported-codec` | "源文件的编码装不进目标容器" | ✔ |
| 用户主动取消 | `canceled` | "任务已取消"（不是"失败"） | ✔ |

### A6. 已知不覆盖（重要）

`npm run smoke` **不覆盖**下面这些，因此不能拿"48 项全部通过"推断它们可用：

| 未覆盖项 | 原因 |
|---|---|
| 旋转自动转正 | 合成样本的 `rotate=90` 元数据未被这份 ffmpeg 保留（探测回来 `rotation=0`），用例自行跳过并如实打印"用例跳过" |
| HDR 色调映射 | 没有 HDR 样本，`zscale`/`tonemap` 滤镜链一次都没执行过 |
| 硬件编码器实际转码 | 冒烟测试不引入 `capabilities.ts`；没有任何用例真的用 QSV/NVENC/AMF 转过文件 |
| 字幕与多音轨映射 | 合成素材没有字幕轨与多音轨 |
| 缩略图避黑场 | `testsrc2` 彩条素材没有黑场，只能证明链路跑得通 |
| 打包产物 | `release/` 从未产出 |
