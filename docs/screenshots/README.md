# 截图目录

`README.md` 通过相对路径引用了本目录下的界面截图。**这些 PNG 全部由命令自动生成，不是手工摆拍的**。

## 怎么生成（两步，顺序不能反）

```bash
npm run smoke:ui:file   # 生成 main / main-with-file / mode-* / main-advanced / queue / settings
npm run smoke:ui:full   # 上一项 + 在应用内真的点一次「开始转换」，额外产出 queue-done.png
```

第一步跑完是 **54/54 通过**，第二步是 **66/66 通过**，都以退出码反映结果。
两步都需：构建项目 → 启动真实 Electron 窗口 → 等待界面骨架挂载**且** `data-store-ready="1"`
→ 通过 `window.__lumenAddFiles()`（与拖拽完全相同的 `addFiles` 路径）加载
`test-assets/samples/sample-h264.mp4` → 依次切到「转换 / 任务队列 / 设置」三页。

> **顺序为什么不能反**：跑过 `--smoke-convert` 的那一轮**不会再写 `queue.png`**
> （否则它会和 `queue-done.png` 变成同一张图，而两张图想表达的恰好是相反的状态）。
> 所以固定工作流是"先 `:file` 拿空队列，再 `:full` 拿完成态"。

## 关于图里的数字

`main-with-file.png` 等图里被加载的是冒烟测试用 `lavfi` 现场合成的 6 秒样本
（`testsrc2` 彩条 + 正弦音，`640×360@30fps`，H.264 + AAC，661 KB），
所以信息面板上的数字是这份样本的真实探测结果——**时长 00:06、661 KB、`640×360`、
`MP4 / QuickTime`、`H264`**，缩略图上还能看到合成时叠加的 `LUMEN 0s` 时间水印。
这正是它作为证据的意义：这些数字不是写死的示例文本，而是 ffprobe 现读出来的。

`queue-done.png` 里的产物大小会**随当前用途而变**：本次自检用的是「发微信 / QQ」（体积上限 100 MB），
上限远大于这个 6.6 秒小样本，因此产物比原片大——**体积上限是"不许超过"，不是"目标值"**。
想看到"压缩"的形态，把用途换成「极小体积」一档（`661 KB → 250 KB`）。

## 注意事项

- **窗口尺寸**：按 `electron/main.ts` 中 `BrowserWindow` 的默认 1360×900 截图（截出的 PNG 为 1344×861，差值是窗口边框）。
- **不要并发运行**：`main.ts` 有单实例锁。已有 Electron 实例在跑时，`npm run smoke:ui*`
  **不会刷新本目录的截图**，而命令本身并不报错——容易把"没跑"误读成"跑过了"。跑之前先确认没有其它实例
  （`Get-Process electron`），并用本目录 PNG 的时间戳确认这一轮确实产出了新图。
- **截图会被覆盖**：每次运行都会重写同名文件，所以不要把手工补拍的图放在同名路径上；
  需要额外截图请用新文件名，并在本文件与 `README.md` 里追加引用。
- **主题一致性**：同一轮运行产出的图主题必然一致。自检在 `createWindow()` **之前**会把
  `appMode` 重置为 `recommended`、主题重置为 `system`，所以截图不受上一轮遗留设置影响。
