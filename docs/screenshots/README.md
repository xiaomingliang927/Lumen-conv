# 截图目录

`README.md` 通过相对路径引用了本目录下的**四张**界面截图。**这些 PNG 全部由命令自动生成，不是手工摆拍的**：

```bash
npm run smoke:ui:file
```

该命令会：构建项目 → 启动真实 Electron 窗口 → 等待界面骨架挂载**且** `data-store-ready="1"`
→ 通过 `window.__lumenAddFiles()`（与拖拽完全相同的 `addFiles` 路径）加载
`test-assets/samples/sample-h264.mp4` → 依次切到「转换 / 任务队列 / 设置」三页 →
截图写入本目录 → 跑 **29 项界面断言** → 以退出码反映结果。

| 文件名 | 内容 | 断言依据 |
| --- | --- | --- |
| `main.png` | 转换页**空状态**：文件列表引导 +「选择视频文件」+ 右侧「未选择文件」 | 标题栏 / 侧边导航 / 文件区 / 详情面板均渲染；空状态引导可见；CSS 变量与主题已应用；preload API 已注入 |
| `main-with-file.png` | 转换页**已加载真实视频**：文件卡片带智能选帧缩略图与时长角标，右侧完整信息面板 + 9 张预设卡片 + 体积预估 | 信息面板 ≥ 5 行（实测 **9 行**）；缩略图 `src` 以 `lumen-media://` 开头；时长角标匹配 `^\d+:\d{2}$`；预设卡片 ≥ 8（实测 **9**）；体积预估含"预计"；详情含分辨率行 |
| `queue.png` | 任务队列页（空队列） | 队列页标题存在 |
| `settings.png` | 设置页：ffmpeg / ffprobe 路径与版本、编码器可用性、转换偏好、外观、缓存 | `.settings .card` ≥ 3（实测 **5 个分组**）；导航高亮落在「设置」 |

## 关于这几张图的内容

`main-with-file.png` 里被加载的是冒烟测试用 `lavfi` 现场合成的 6 秒样本
（`testsrc2` 彩条 + 正弦音，`640×360@30fps`，H.264 + AAC，661 KB），
所以信息面板上的数字是这份样本的真实探测结果——**时长 00:06、总码率 902 kbps、`640×360 · 30 fps`、
`H264 · High`、`yuv420p`、`AAC · 单声道 · 44.1 kHz`**，缩略图上还能看到合成时叠加的 `LUMEN 0s` 时间水印。
这正是它作为证据的意义：这些数字不是写死的示例文本，而是 ffprobe 现读出来的。

`main.png` 与 `queue.png` 抓的是**空状态**，适合证明"界面能起来、样式与空状态引导正常"。
若要在 README 里体现"转换中/已完成"的队列形态，可跑：

```bash
npm run smoke:ui:full   # 额外在应用内真的点一次「开始转换」并等任务跑到终态
```

它会额外产出 `queue-done.png`（含已完成任务的队列卡片），并追加 5 项断言：
任务已创建、状态为已完成、产物文件存在且大于 1 KB、进度到达 100%、命令文本已记录，
合计 **26 项检查**。

## 注意事项

- **窗口尺寸**：按 `electron/main.ts` 中 `BrowserWindow` 的默认 1360×900 截图（截出的 PNG 为 1344×861，差值是窗口边框）。
- **不要并发运行**：`main.ts` 有单实例锁。已有 Electron 实例在跑时，`npm run smoke:ui` **不会刷新本目录的截图**，
  而命令本身并不报错——容易把"没跑"误读成"跑过了"。跑之前先确认没有其它实例（`Get-Process electron`），
  并用本目录 PNG 的时间戳确认这一轮确实产出了新图。
- **截图会被覆盖**：每次运行都会重写同名文件，所以不要把手工补拍的图放在同名路径上；
  需要额外截图（例如「高级选项」展开态）请用新文件名（如 `advanced.png`），并在 README 里追加引用。
- **主题一致性**：四张图由同一次运行产出，主题必然一致；若之后手工补拍，请注意与现有四张保持同一主题。
